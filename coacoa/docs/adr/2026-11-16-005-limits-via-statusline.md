# Context
Проценты использования (`rate_limits.five_hour` и `rate_limits.seven_day`: `used_percentage`, `resets_at`) по документации есть только во входе `statusLine`. Хуки их не получают.

# Decision
`statusline.ps1` выводит строку статуса и вызывает `Limits.psm1`. Тот сравнивает проценты с порогами `[80, 90]` и хранит в `limits.json` уже сработавшие пороги для каждой пары (окно, `resets_at`). Новое событие «Лимит» отправляется только при новом пересечении порога. Если у пользователя уже есть `statusLine`, установщик не заменяет его, а прописывает вызов существующей команды и добавляет к её выводу свою часть.

# Consequences
+ Предупреждение приходит заранее, а не после того, как лимит уже достигнут.
− Если `statusLine` не работает в desktop-приложении (риск R-1), остаются только запасные сигналы: `StopFailure` с `rate_limit` (тип `error`) и `Notification` с типами `quota_auto_resume_*`.

# Alternatives
- **Опрос API использования:** не документирован для подписок и требует сети.
- **Только `StopFailure rate_limit`:** сообщает уже после того, как лимит достигнут, — не выполняет G-4.
