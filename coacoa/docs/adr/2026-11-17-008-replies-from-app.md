# ADR-008: Ответы из приложения — разрешения, вопросы Claude, быстрые ответы

- **Статус:** принято, 2026-11-17
- **Контекст:** пользователь хочет решать запросы разрешения и отвечать Claude из трея, окна «Сеансы» и с телефона, не переключаясь в окно Claude. Статус «Нужно разрешение» не должен «зависать», когда запрос уже решён.

## Факты (документация хуков Claude Code, 2026-11-17)

- **`PermissionRequest`** — синхронный хук. Он получает `tool_name`, `tool_input` и `permission_suggestions`, а отвечает `hookSpecificOutput.decision`: `behavior` allow/deny, `updatedPermissions` (только для allow), `message` (только для deny). Для `AskUserQuestion` и `ExitPlanMode` нужен `updatedInput`, так передаются ответы на вопрос. Время ожидания по умолчанию — 600 с. Если хук ничего не выводит, решение принимается обычным путём, через диалог Claude.
- **SDK и приложение Claude:** при колбэке `canUseTool` действует «кто решит первым», то есть диалог Claude и наш хук соревнуются.
- **`asyncRewake`** — фоновый хук. Если он завершается с кодом 2, он будит Claude даже в простаивающем сеансе, а его stderr или stdout доходит до Claude напоминанием. Ограничение `timeout` соблюдается.

## Решение

1. **Обмен файлами** в `<DataRoot>\requests` (`Requests.psm1`):
   - хук пишет `perm-<id>.json` (в нём есть его `pid`) и опрашивает `perm-<id>.decision.json`;
   - трей и веб-API записывают решение.

   Решения пишет только приложение, а хук только читает, поэтому гонок нет.
2. **Хук `PermissionRequest`** (`hook-bridge.ps1 permreq`, синхронный, `timeout` 3700 с):
   - отправляет трею событие `request`: уведомление «Нужно разрешение» и статус сеанса;
   - ждёт решения `approvals.waitSeconds` секунд (по умолчанию 600) и возвращает JSON;
   - нет решения — молчит, и всё решает диалог Claude.

   В CLI хук может выполняться **до** диалога, поэтому там по умолчанию не ждёт (`approvals.cliWaitSeconds = 0`).
3. **Вопросы Claude** (`AskUserQuestion`):
   - один вопрос без множественного выбора — варианты ответа кнопками плюс «Свой ответ…»; ответ уходит через `updatedInput.answers`;
   - несколько вопросов — кнопка «Открыть Claude».

   План (`ExitPlanMode`) — кнопки «Утвердить» и «Отклонить».
4. **Быстрые ответы** (`hook-bridge.ps1 replywait`, второй хук `Stop` с `asyncRewake`):
   - после «Готово» хук ждёт `reply-<session>.txt` до `quickReplies.minutes` минут;
   - пришёл ответ — хук пишет его в stderr и завершается с кодом 2, и Claude продолжает работу;
   - вы написали в Claude сами (`UserPromptSubmit`) — трей снимает ожидание, и хук завершается.
5. **Статус:**
   - решение из приложения сразу переводит сеанс в «Работает»;
   - если процесс хука завершился без нашего решения (вы ответили прямо в Claude, истекло время), трей видит это по `pid`, убирает запрос и тоже переводит сеанс в «Работает»;
   - уведомление Claude «Нужно разрешение» по тому же сеансу в течение 30 с после нашего запроса не дублируется.
6. **Телефон и браузер:** `/api/sessions` отдаёт запрос и `can_reply`, а `POST /api/decision` и `/api/reply` принимают ответ. Это работает для сеансов ПК: хуки Mac асинхронные и ответа не ждут.

## Последствия

- На каждый запрос разрешения запускается PowerShell (около 0,4 с) до решения.
- На каждый простаивающий сеанс с включёнными быстрыми ответами в фоне ждёт один процесс PowerShell, пока не истечёт срок или не придёт ответ.
- Быстрый ответ приходит Claude напоминанием от хука, а не обычным сообщением в чате. В истории чата он виден как сообщение хука.
- Ответы из приложения проверены вживую в приложении Claude (см. README).
