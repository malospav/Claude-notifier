# Story s_003_01 — Window: поиск и фокус окна сессии

## Description
Находить окно сессии Claude и выводить его на передний план — основа перехода по клику.

Эпик: [e_003](../e_003.md). Зависит от: [s_001_01](s_001_01.md).

## Acceptance Criteria
1. `Get-SessionWindow -Origin cli|desktop` возвращает `@{hwnd; pid}` по алгоритму из архитектуры §4 (консоль → root owner; иначе обход родителей до видимого `MainWindowHandle`).
2. Если окно не найдено, возвращается `@{hwnd=0; pid=<claude pid или 0>}` без исключений.
3. `Set-SessionWindowFocus -Hwnd <n>`: если `IsWindow` = false → `closed`; иначе `ShowWindow(SW_RESTORE)` для свёрнутого + `SetForegroundWindow`; возвращает `focused|flashed|closed`.
4. Если `SetForegroundWindow` вернул false → `FlashWindowEx` и результат `flashed`.
5. Win32-функции объявлены одним `Add-Type` с проверкой, что тип ещё не загружен.

## Micro-context (architecture.md)
```markdown
**Поиск окна (Window.psm1):** `origin` берётся из `CLAUDE_CODE_ENTRYPOINT` (`claude-desktop` → desktop, иначе cli). Для CLI окно ищется так: `GetConsoleWindow()` → `GetAncestor(GA_ROOTOWNER)`. Для Windows Terminal это даёт окно WT, для conhost — саму консоль. Для desktop и как fallback: обход родительских процессов до первого с видимым `MainWindowHandle`. Фокус: `ShowWindow(SW_RESTORE)` + `SetForegroundWindow`. Если окно уже закрыто (`IsWindow` = false), событие помечается `closed`.
```

```markdown
| R-1 | `statusLine` может не работать в desktop-приложении (PRD OQ-2) | Проверить в QA. Fallback: `StopFailure` с `rate_limit` и `Notification` с `quota_auto_resume_*` |
| R-2 | `SetForegroundWindow` из фонового процесса могут заблокировать | Обработчик протокола запускается кликом пользователя и получает право на передний план. Если не сработает — мигание кнопки на панели задач (`FlashWindowEx`) |
| R-3 | При запуске трея из bridge может мелькнуть окно | Запуск через `conhost.exe --headless powershell.exe …` |
| R-4 | Конкретный чат в desktop открыть нельзя (deep-link не документирован) | Сохраняется `host_session_id`, чтобы добавить переход позже без смены схемы события |
```

## Implementation Hints
