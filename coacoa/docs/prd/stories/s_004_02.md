# Story s_004_02 — statusline.ps1 и его установка

## Description
Строка статуса показывает модель, контекст и лимиты и одновременно отправляет предупреждения о лимитах.

Эпик: [e_004](../e_004.md). Зависит от: [s_004_01](s_004_01.md), [s_001_03](s_001_03.md), [s_001_05](s_001_05.md).

## Acceptance Criteria
1. Выводит одну строку: «<модель> · ctx <N>% · 5ч <N>% · нед <N>%»; отсутствующие части пропускаются.
2. Для каждого результата `Test-NotifierLimits` отправляет событие `limit` (`Send-NotifierEvent`, без автозапуска трея).
3. Если в `settings.json` уже был `statusLine`, установщик сохраняет его команду в `config.json` (`chainStatusLine`); скрипт вызывает её с тем же stdin и печатает её вывод перед своим.
4. Установщик записывает `statusLine: {type: command, command: powershell.exe -NoProfile -File <app>\statusline.ps1}`; деинсталлятор восстанавливает прежний `statusLine`.
5. Любая ошибка → печатается хотя бы имя модели, exit 0.

## Micro-context (architecture.md)
```markdown
- **Security:** входящий JSON хука проверяется по полям и типам, неизвестные поля отбрасываются (S-1). Превью попадает в toast XML только после XML-экранирования (S-5). Установщик делает резервную копию `settings.json` (`settings.json.bak-<ts>`) перед изменением. Свои записи он помечает путём к `%LOCALAPPDATA%\claude-notifier\app\` и удаляет только их. Без прав администратора; пишутся только HKCU (`Software\Classes\claude-notifier`, `Software\Classes\AppUserModelId\ClaudeNotifier`).
- **Logging & observability:** `%LOCALAPPDATA%\claude-notifier\log.txt`, уровни INFO/WARN/ERROR, ротация в `log.1.txt`.
- **Configuration / feature flags:** `config.json` — включение типов событий, путь к WAV для каждого типа, пороги лимитов `[80, 90]`, длина превью `200`. Неверные значения заменяются значениями по умолчанию с WARN в логе.
- **I18n & Accessibility:** строки интерфейса на русском лежат в одном словаре в `Config.psm1`; файлы в UTF-8 с BOM. Тип события дублируется текстом и звуком.
```

- Команда statusLine — строка для оболочки (Git Bash или PowerShell): пути через `/`, `powershell.exe` без кавычек — работает в обеих.
- Прежний statusLine сохраняется **целиком** (с `padding` и т. п.) в `config.json` → `chainStatusLine` и восстанавливается при удалении. Пишется в config.json **до** settings.json: если config.json повреждён, установка прерывается, settings.json не меняется. Повторная установка не принимает наш statusLine за «прежний».
- Прежняя строка вызывается в той же оболочке, что у Claude Code (Git Bash, иначе PowerShell), с таймаутом 3 с.
- Найдено и исправлено: `Process.StandardInput` в .NET Framework пишет BOM, если кодировка консоли — UTF-8 с BOM; прежняя строка статуса получила бы испорченный stdin. На время запуска ставится UTF-8 без BOM.
- Вывод пишется байтами UTF-8 (иначе консоль Windows перекодирует «5ч», «нед», «·» в CP866).
- События о лимитах отправляются без запуска трея; если трей не запущен — WARN в лог.
- R-1 (работает ли statusLine в desktop-приложении) здесь не проверен: нужна установка в настоящий профиль — перенесено в s_005_03.
