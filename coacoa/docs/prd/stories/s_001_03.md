# Story s_001_03 — Ipc: named pipe клиент и сервер

## Description
Передавать события между процессами по named pipe, доступному только текущему пользователю.

Эпик: [e_001](../e_001.md). Зависит от: [s_001_01](s_001_01.md).

## Acceptance Criteria
1. Имя pipe: `claude-notifier-<USERNAME>`.
2. `Send-NotifierEvent -Event <obj> -TimeoutMs 50` пишет одну строку JSON (UTF-8) и возвращает `$true`/`$false`; не выбрасывает исключений.
3. `Start-NotifierPipeServer -Queue <ConcurrentQueue>` в отдельном runspace принимает клиентов в цикле и кладёт разобранные события в очередь.
4. DACL сервера даёт доступ только SID текущего пользователя.
5. Строка длиннее 64 КБ или невалидный JSON отбрасывается с WARN; сервер продолжает работу.
6. `Stop-NotifierPipeServer` корректно завершает runspace и освобождает pipe.

## Implementation Hints
`System.IO.Pipes.PipeSecurity` + `PipeAccessRule` для `[Security.Principal.WindowsIdentity]::GetCurrent().User`. Тест-сервер с уникальным именем pipe через параметр `-PipeName`.

## Test Plan

- [ ] Невалидный JSON → очередь пуста, сервер принимает следующее событие.
