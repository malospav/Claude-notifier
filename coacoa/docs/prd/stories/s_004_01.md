# Story s_004_01 — Limits: пороги и дедупликация

## Description
Решать, когда предупреждать о лимите: каждый порог один раз за окно использования.

Эпик: [e_004](../e_004.md). Зависит от: [s_001_01](s_001_01.md).

## Acceptance Criteria
1. `Test-NotifierLimits -StatusJson <str>` читает `rate_limits.five_hour` и `rate_limits.seven_day` (`used_percentage`, `resets_at`).
2. Для каждого окна возвращает новые пересечённые пороги из конфига (`[80, 90]`); уже сработавшие для той же пары (окно, `resets_at`) не возвращаются.
3. Состояние хранится в `limits.json`; смена `resets_at` сбрасывает сработавшие пороги окна.
4. Нет `rate_limits` или окна → пустой результат без ошибок.
5. Скачок с 70 % на 95 % → одно событие с наибольшим порогом (90), 80 помечается сработавшим.
6. Событие `limit`: `preview` = «5 ч: 92 %, сброс в HH:mm» / «Неделя: 81 %, сброс <dd.MM HH:mm>» (локальное время).

Установщик делает резервную копию `settings.json` (`settings.json.bak-<ts>`) перед изменением. Свои записи он помечает путём к `%LOCALAPPDATA%\claude-notifier\app\` и удаляет только их. Без прав администратора; пишутся только HKCU (`Software\Classes\claude-notifier`, `Software\Classes\AppUserModelId\ClaudeNotifier`).
- **Logging & observability:** `%LOCALAPPDATA%\claude-notifier\log.txt`, уровни INFO/WARN/ERROR, ротация в `log.1.txt`.
- **Configuration / feature flags:** `config.json` — включение типов событий, путь к WAV для каждого типа, пороги лимитов `[80, 90]`, длина превью `200`. Неверные значения заменяются значениями по умолчанию с WARN в логе.
