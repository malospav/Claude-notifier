# Story s_005_02 — История событий и меню

## Description
Пользователь видит последние события в меню трея и может перейти к любой сессии.

Эпик: [e_005](../e_005.md). Зависит от: [s_005_01](s_005_01.md).

## Acceptance Criteria
1. `Add-NotifierHistory` хранит ≤ 100 событий в `history.json` (старые вытесняются); запись атомарная (temp + move).
2. Меню «История ▸» показывает 20 последних: «HH:mm · <Тип> · <project>»; у `closed` — пометка «(закрыта)».
3. Клик по пункту запускает `focus-handler.ps1` с URI события (тот же путь, что у toast).
4. История переживает перезапуск трея.
5. Повреждённый `history.json` → пустая история + WARN, файл переименован в `.corrupt`.

```markdown
| Событие → toast (P95) | ≤ 1 с | bridge: старт PS ≈ 130 мс + pipe ≤ 50 мс + toast; трей разбирает очередь каждые 100 мс |
| Хук-мост | ≤ 500 мс, всегда exit 0 | `async: true` — Claude Code не ждёт bridge; внутри всё обёрнуто в try/catch → exit 0; таймаут подключения к pipe 50 мс |
| Падение трея | Не влияет на Claude Code | Нет pipe → bridge запускает трей (FR-6), повторяет отправку 3 раза по 300 мс, затем пишет в лог и выходит с 0 |
| Безопасность | Только локально; без сети; без секретов в логе | Pipe с DACL текущего пользователя; превью не пишется в лог; переменные `*TOKEN*` и `*KEY*` не читаются |
| Совместимость | Smart App Control On | Только подписанные Microsoft `powershell.exe`, `conhost.exe` и .NET Framework (ADR-001) |
| Ресурсы | ≤ 150 МБ RAM, ≈ 0 % CPU в простое | Один процесс трея; таймер 100 мс без опроса диска; сервер pipe блокируется в фоновом runspace; в простое — EmptyWorkingSet через 30 с и каждые 5 мин |
```

- Новые файлы: `src/lib/History.psm1`, `tests/unit/s_005_02.Tests.ps1`.
- Изменены: `src/ClaudeNotifier.Tray.ps1` (запись в историю, подменю «История», запуск обработчика, общий нативный тип `ClaudeNotifier.TrayNative`), `src/focus-handler.ps1` (локальные функции чтения/записи заменены на `History.psm1`), тесты s_003_02 (битая история теперь переименовывается в `.corrupt`) и s_005_01 (меню «История, Выход»).
- Событие пишется в историю **до** показа toast: клик по уведомлению сразу находит его в `history.json`. Ошибка записи истории (ERROR) не мешает показу.
- Подменю перечитывает `history.json` при каждом открытии — пометка «(закрыта)», поставленная обработчиком клика, видна сразу.
- Перед запуском обработчика трей вызывает `AllowSetForegroundWindow(ASFW_ANY)`, чтобы новому процессу разрешили вывести окно на передний план.
- Задержка «событие → показ» с записью истории: P95 211 мс (было ≈ 150 мс), в пределах ≤ 1 с.
- Ограничение: трей и обработчик клика пишут `history.json` независимо (атомарная замена файла), при одновременной записи одно изменение может потеряться (например, пометка `closed`). Для однопользовательской утилиты считаю допустимым.
