# claude-notifier

Уведомления Windows 11 о событиях Claude Code: **Готово**, **Нужно разрешение**, **Ошибка**, **Лимит**. У каждого типа свой звук, в уведомлении видно начало ответа Claude, история событий доступна из иконки в трее, а окно «Сеансы Claude» показывает все активные сеансы и их статус.

Работает только на компонентах Windows: Windows PowerShell 5.1 и .NET Framework. Устанавливать ничего не нужно, и Smart App Control программу не блокирует.

## Требования

- Windows 11 (проверено на 10.0.26200, Smart App Control включён).
- Windows PowerShell 5.1 — есть в системе.
- Claude Code: desktop-приложение или CLI.
- Права администратора не нужны.

## Установка

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Установщик делает следующее:

1. Копирует `src\` в `%USERPROFILE%\.claude-notifier\app\`.
2. Добавляет в `~/.claude/settings.json` хуки `Stop`, `Notification`, `StopFailure` (уведомления) и `SessionStart`, `UserPromptSubmit`, `SessionEnd` (статусы для окна «Сеансы»). Хуки асинхронные, Claude их не ждёт. Частые хуки запускают встроенный в Windows `curl.exe` (подписан Microsoft): он за ~20 мс отправляет JSON хука трею на `127.0.0.1:47611`, а окно сеанса трей находит сам — без запуска PowerShell на каждое событие (раньше ~0,45 с процессора и ~60 МБ памяти на хук). Трей принимает только запросы со своим заголовком, поэтому страница в браузере подделать событие не может. `SessionStart` остаётся PowerShell-мостом: заодно запускает трей, если он не работает; так же — запрос разрешения и ожидание быстрого ответа.
3. Прописывает строку статуса `statusLine`. Если у вас уже была своя строка статуса, она сохраняется в `config.json` (`chainStatusLine`) и показывается первой.
4. Регистрирует URL-протокол `claude-notifier:` в HKCU. Через него трей открывает окно сессии.
5. Создаёт ярлыки **Claude Notifier** в меню «Пуск» и на рабочем столе (`-NoDesktopShortcut` — без ярлыка на столе). У ярлыка своя иконка и свой идентификатор приложения, поэтому на панели задач и в уведомлениях видно «Claude Notifier», а не «Windows PowerShell».

Перед изменением `settings.json` рядом сохраняется копия `settings.json.bak-<дата>`. Чужие хуки и настройки установщик не трогает. Повторный запуск безопасен.

Программа в трее запускается сама при первом событии или по щелчку на ярлыке **Claude Notifier**.

## Удаление

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\uninstall.ps1          # настройки и история остаются
powershell -NoProfile -ExecutionPolicy Bypass -File .\uninstall.ps1 -Purge   # удалить всё
```

Удаляются только записи claude-notifier. Прежняя строка статуса восстанавливается. Перед удалением закройте трей: правый клик по точке в трее → «Выход».

## Как пользоваться

- **Уведомление** приходит, когда Claude закончил, ждёт разрешения или ответа, упал с ошибкой или подходит к лимиту (80 % и 90 % пятичасового и недельного окна).
- **Настройки по разделам.** Страница настроек шторки — боковое меню (Уведомления, Ответы, Сеансы, Шторка, Маскоты, Система) и строки выбранного раздела в две колонки, без прокрутки; событие и его звук стоят рядом.
- **Шторка вверху экрана.** Маленькая чёрная полоска у верхнего края монитора (по умолчанию — второго, по центру). Слева крупный персонаж главного сеанса (того, что ждёт решения, иначе выбранного), справа маленькие персонажи остальных. Персонаж — настоящая 3D-модель мордочки сфинкса (WPF 3D из .NET Framework, ничего ставить не нужно): гладкие сетки с нормалями, трёхточечный свет (ключевой, заполняющий, контровой), большие уши-раковины, глянцевые глаза с бликами. Каждая поза рендерится один раз, уменьшается до итогового размера и сохраняется на диск (`cache\sprites-…`): при следующих запусках кадры берутся оттуда, и WPF вообще не загружается (трей занимает ~100 МБ памяти вместо ~210). Промежуточные повороты головы смешиваются из соседних готовых кадров, так что движения плавные без новых рендеров. Шторка рассчитана на работу в фоне: новых 3D-кадров не больше 3 в секунду в свёрнутом виде (12 — в раскрытом), у маленьких мордочек шаг поз крупнее, по таймеру перерисовываются только персонажи, а не вся шторка, свёрнутая анимируется с частотой 20 кадров/с, при заблокированном экране, во сне и когда вас нет за компьютером (2 минуты без ввода, шторка свёрнута) анимация стоит, таймер трея в покое срабатывает 4 раза в секунду вместо 10, а без вас — раз в секунду. Шторка всегда поверх остальных окон: если её перекроет другое окно «поверх всех» (плеер, панель, всплывающее окно), через долю секунды она снова поднимается наверх, не забирая фокус. Окно шторки — layered с попиксельной прозрачностью: края и скругления сглажены, вне шторки окно прозрачно и пропускает щелчки. Раскрытие и сворачивание — пружиной без рывков на любой странице: окно не меняет размер, внутри плавно растёт сама фигура, а содержимое проявляется из чёрного и обрезается её краем; кадры идут в такт обновлению экрана, а кадры крупных сфинксов заранее рендерятся в фоне, пока шторка свёрнута. После прогрева свёрнутая шторка берёт около 2 % одного ядра, раскрытая — около 4–5 %, пока сфинкс следит за мышью — около 8 %. Если 3D недоступно, рисуется прежняя плоская мордочка. Кожа слегка подкрашена цветом статуса, поведение тоже: персиковый **думает**, пока Claude работает — взгляд вверх и в сторону, медленно гуляет, рядом облачко «…» с бегущими точками; на каждое новое действие Claude (правка файла, команда) — «Ага!»: глаза округляются, уши торчком, в облачке «!»; долго без действий — задумался: прищур и кончик языка; агенты — огоньки кружат вокруг головы, по одному на агента; «Похоже, остановился» — сонные глаза и «z». Раз в 6–12 с — случайная мелочь: двойное моргание, дёрнул ухом, глянул на вас, изредка зевнул. В раскрытой шторке сфинкс плавно поворачивает голову за курсором, когда мышь двигается рядом (глаза сидят в глазницах с веками и не «плавают»); янтарный ждёт разрешения — наклоняет голову, глаза ещё больше, «дышит»; розовый ждёт ответа — спокойно моргает; красный — ошибка: уши обвисли, глаза-крестики; серый — сеансов нет, спит и медленно кивает. Если в Windows выключены эффекты анимации, котики неподвижны. Маскот выбирается в настройках шторки, раздел «Маскоты»: свой для этого ПК и для каждого подключённого устройства (сеансы с Mac рисуются его маскотом) — 3D-сфинкс или **огонёк** — плоское пламя с жёлтой серединкой и мордочкой: работает — пламя пляшет, взгляд гуляет, облачко «…»; «Ага!» — вспыхивает, глаза «> <», искры-чёрточки; задумался — пламя ниже, прищур; ждёт разрешения — янтарный, подпрыгивает, глаза круглые; ждёт ответа — тихо горит и моргает; ошибка — красный, глаза-крестики, дымок; остановился — тусклый и сонный; сеансов нет — спящий уголёк; агенты — искры вокруг. Огонёк рисуется векторно и почти не нагружает процессор.

  Шторка — главное окно приложения: щелчок по ней, по точке в трее, ярлык «Claude Notifier», пункты меню трея и горячая клавиша раскрывают её. Она работает в своём потоке, поэтому персонажи и раскрытие не подвисают, даже когда трей занят. Вверху вкладки **Главная**, **Статистика**, **Устройства**, **Настройки**; после разделителя **+** — новый сеанс Claude Code в папке проекта (Windows Terminal, иначе PowerShell) и **терминал** — перейти к окну сеанса. Справа плашка «Claude 34 %» с расходом пятичасового лимита (данные старше 30 минут не показываются), звук (выключить звук всех уведомлений) и «закрыть». На главной — выбранный сеанс крупно: статус, что делает агент, начало последнего ответа или запрос и кнопки ответа; щелчок по карточке открывает **полный последний ответ** Claude (из журнала сеанса, с прокруткой) и все варианты ответа внизу; стрелка в углу — перейти к окну; справа остальные сеансы плашками (щелчок выбирает). «Статистика», «Устройства» и «Настройки» — те же данные и переключатели, что были в окне; длинные страницы делают шторку выше и прокручиваются колесом. Щелчок мимо или «закрыть» сворачивают шторку. Монитор и положение (слева, по центру, справа) — в «Настройках» шторки. Выключить шторку («Шторка вместо окна») — вернётся прежнее окно «Сеансы» и мини-окно у трея.

- **Точка в трее** показывает общий статус сеансов:

  | Точка | Значит |
  |---|---|
  | 🟠 оранжевая | хотя бы один сеанс ждёт разрешения |
  | 🔴 красная | ошибка |
  | 🔵 синяя | Claude работает |
  | 🟢 зелёная | все сеансы ждут вашего ответа |
  | ⚪ серое кольцо | сеансов нет |

  Если вас ждут два сеанса и больше (запрос разрешения, ошибка или свежее «Ждёт ответа»), на точке видно их **число**. Наведите курсор — подсказка покажет, сколько сеансов в каждом статусе. **Щелчок** открывает мини-окно над треем: список сеансов с кнопками ответа (закрывается щелчком мимо или Esc). **Двойной щелчок** — полное окно. **Win+Shift+C** открывает и закрывает мини-окно с клавиатуры (если сочетание занято другой программой — **Ctrl+Alt+C**). Правый щелчок — меню **Сеансы**, **Устройства**, **Настройки**, **Статистика**, **История** (последние 20 событий; щелчок выводит на передний план окно сессии) и **Выход**.
- **Окно «Сеансы»** — строка на каждый активный сеанс, сгруппированная по устройству («Этот ПК», «MacBook Air»…): цветная точка и статус («Работает», «Ждёт ответа», «Нужно разрешение», «Ошибка»), проект, где идёт («Приложение», «Терминал» или имя Mac), сколько времени в этом статусе и начало последнего ответа Claude. Сверху — сеансы, которые ждут вас.

  Справа во второй строке — **заполненность контекста**: «контекст 72 %» и короткая полоска (синяя, с 85 % оранжевая, с 95 % красная). Пока сеанс работает, трей обновляет её каждые 15 с по журналу сеанса. Когда контекст доходит до 85 %, приходит уведомление «Контекст почти заполнен»: скоро Claude сожмёт историю, можно начать новый сеанс или выполнить `/compact`. Размер окна контекста — оценка: 1 млн токенов у моделей Claude 5 (кроме Haiku), у моделей с `[1m]` и если сеанс уже был больше 200 тыс.; иначе 200 тыс.

  Превью ответа показывается без разметки Markdown (без `**`, обратных кавычек, `#` и адресов ссылок). Карточки раскрываются и сворачиваются плавно, пружиной (повторный щелчок по раскрытой карточке сворачивает её, новый сеанс «вырастает» в списке). Если в Windows выключены эффекты анимации — сразу, без движения. Щелчок по строке раскрывает подробности: вверху плашки с главным — заполненность контекста, примерная стоимость, сколько файлов изменено; ниже таблица «подпись — значение»: полный последний ответ, когда начат и сколько идёт, контекст в процентах и токенах, токены ответов, число запросов, действий и сжатий истории, **сколько файлов изменено** (и последние из них), **какие инструменты вызывались чаще всего**, **последняя команда** (длинные пути сокращены: папка пользователя — `~`, середина пути — `…`), **примерная стоимость сеанса** по ценам API вместе с его агентами (и ваш последний запрос, если это включено в настройках). Под подробностями — кнопки **Изменённые файлы · N** (меню из 15 последних файлов: файл открывается в VS Code, а без него показывается в Проводнике) и **Папка проекта**. Те же пункты есть в меню по правому щелчку. У статуса «Работает» точка мягко пульсирует.

  **Поиск и фильтр.** Когда сеансов больше 5, над списком появляется строка поиска (в любой момент — **Ctrl+F**): ищет по имени, проекту, последнему ответу и вашему запросу. Рядом фильтры **Все · Ждут меня · Работают**. Esc очищает поле, второй Esc закрывает строку.

  **Группы по проектам.** Когда сеансов 4 и больше, сеансы одного проекта сворачиваются в одну строку: «shop · 3 сеанса» и сколько из них в каком статусе (точка — самый срочный). Щелчок по строке раскрывает группу, повторный — сворачивает. Сеанс, который ждёт вашего решения (запрос разрешения или ошибка), виден и в свёрнутой группе; закреплённые сеансы в группы не попадают.

  **Неактивные сеансы.** Сеансы, которые «Ждут ответа» дольше 2 часов, собираются в конце списка в свёрнутую строку «Неактивные · N сеансов». Раскрытая, она показывает эти сеансы и кнопку **Убрать все из списка**. Закреплённые сеансы и сеансы с запросом туда не попадают. Убранный сеанс вернётся в список при следующем событии.

  **Агенты.** Если Claude работает через агентов, карточка показывает «Работает агент» или «Работают агенты · 3», а под статусом — по строке на агента (до трёх): что ему поручено и что он делает сейчас (последнее действие: файл, команда), с мягко пульсирующей точкой. Агент считается работающим, пока он не завершён и писал в свой журнал в последние 30 минут.

  **Сеанс завис или упал.** Если сеанс «Работает», а его журнал (вместе с журналами субагентов) не меняется 10 минут, приходит уведомление «Сеанс, похоже, остановился», а карточка становится красной: «Похоже, остановился» и сколько уже тишина. Как только в журнале появится новая запись, карточка вернётся к «Работает». Если в журнале появилась ошибка API (перегрузка серверов, лимит запросов, обрыв связи), а хук `StopFailure` о ней не сообщил, трей сам покажет уведомление «Ошибка» с понятным текстом.

  Двойной клик или Enter по строке выводит окно сеанса на передний план. Правый клик по строке:
  - **Переименовать…** — своё имя сеанса вместо имени проекта (проект остаётся виден во второй строке);
  - **Закрепить сверху** — сеанс всегда первым в списке (значок булавки);
  - **Без уведомлений** — статус обновляется, но уведомлений и звука по этому сеансу нет (значок «без звука»);
  - **Убрать из списка** (или Del).

  Имя, закрепление и «без уведомлений» сохраняются и после возобновления сеанса (`claude --resume`).

  **Запрос без ответа не потеряется.** Если запрос разрешения ждёт дольше 3 минут, уведомление повторяется («Всё ещё ждёт ответа») — до 3 раз, каждые 3 минуты. Точка в трее при этом мигает, а у карточки точка пульсирует чаще и шире. Окно обновляется само каждые 5 с и сразу при новом событии. Завершённые сеансы пропадают: по хуку `SessionEnd`, когда закрыт процесс или окно сеанса, или если 24 ч не было событий.

  Внизу окна — **две полосы расхода**: пятичасовой и недельный лимит Claude, с временем сброса (синяя, от 75 % оранжевая, от 90 % красная). Данные — с сервера Anthropic, раз в 5 минут, если вы вошли в **Claude Code CLI** (токен из `~/.claude/.credentials.json` уходит только в Anthropic, как у команды `/usage`); иначе — из строки статуса CLI. Приложение Claude лимиты никуда не передаёт, поэтому без входа в CLI вместо двух полос — одна строка «Лимиты Claude · нет данных». По этим же данным приходят предупреждения о 80 % и 90 % лимита.

  Заголовок окна в стиле Windows 11: слева иконки **Статистика**, **Устройства** и **Настройки**, справа кнопки «Свернуть», «Развернуть» и «Закрыть». Повторный щелчок по иконке или стрелка «Назад» возвращают к сеансам. Окно перетаскивается за заголовок, двойной щелчок разворачивает, работают Snap и изменение размера.

- **Статистика** (иконка-график в заголовке окна): токены ответов Claude и время работы за 7 дней. Вверху — столбцы по дням (сегодня выделен) и итог недели, ниже — проекты за сегодня и за неделю: время, число запросов, токены. Данные берутся из журналов Claude Code на этом ПК (`~/.claude/projects`; туда пишут и CLI, и приложение Claude). Время — пока сеанс активен: паузы дольше 5 минут не считаются, время субагентов не прибавляется. Рядом — **примерная стоимость** по ценам API Anthropic: за сегодня, за неделю и по каждому проекту. Учитываются вход, запись и чтение кэша, ответы и быстрый режим, цена — по модели каждого ответа. Если у вас подписка Claude, вы платите по её тарифу, а эта цифра показывает, сколько стоили бы те же запросы через API. Считается в фоне при открытии страницы (первый раз — около секунды), дальше читаются только новые строки.

  Оформление в стиле Apple: сгруппированные списки, тумблер, кнопки-капсулы, системная палитра Apple; светлая или тёмная тема — по настройке Windows. Движение сдержанное: отклик сразу при нажатии, короткие ease-out-переходы; если в Windows выключены эффекты анимации, движения нет.
- **Открыть приложение** — ярлык **Claude Notifier** на рабочем столе или в меню «Пуск». Если трей не запущен, ярлык запускает его и открывает окно «Сеансы»; если запущен — просто открывает окно. Ярлык можно закрепить на панели задач или на начальном экране.
- **Ответы из приложения** (для сеансов этого ПК; подробности — ADR-008):
  - **Запрос разрешения** — карточка сеанса раскрывается с командой или файлом и кнопками **Разрешить**, **Разрешать всегда** (если Claude предлагает правило) и **Запретить**. Можно ответить и в самом Claude — кто ответил первым, тот и решил; запрос в приложении исчезнет сам.
  - **Вопрос Claude** (с вариантами ответа) — варианты кнопками и **Свой ответ…**; план — **Утвердить** / **Отклонить**.
  - **Быстрый ответ** — у сеанса, который закончил и ждёт вас: **Продолжай**, **Да**, **Нет** или **Ответить…** со своим текстом. Claude получает ответ и продолжает работу, переключаться в его окно не нужно. В чате Claude ответ виден как сообщение хука с подписью «Stop hook blocking error» — это стандартная подпись Claude для сообщений хука, а не ошибка.
  - Всё это есть в окне «Сеансы», в мини-окне у трея и на странице для телефона.
  - Статус сразу меняется на «Работает»: и когда вы ответили в приложении, и когда ответили прямо в Claude.
- **Настройки** (иконка-шестерёнка в заголовке окна): включение каждого типа уведомлений и его звук (системный или свой WAV, с прослушиванием), ответы из приложения, показ вашего запроса в подробностях; группа **Внимание** — предупреждение о контексте, «сеанс завис или упал», напоминания о запросах, «Готово» только после долгих задач, группировка по проектам, горячая клавиша; **запуск при входе в Windows**, папка данных.
- **Кнопки в уведомлении.** У запроса разрешения — «Разрешить», «Всегда», «Запретить» (у вопроса — его варианты, у плана — «Утвердить» и «Отклонить»), у «Готово» — быстрые ответы «Продолжай», «Да», «Нет». Нажатие ловит сам трей, как кнопку в карточке; свой ответ — по-прежнему в окне. Если сеанс уже не ждёт (ответили в Claude), нажатие ничего не делает.
- **Клик по самому уведомлению** только закрывает его. Почему так — в разделе «Известные ограничения».

## Другие устройства: Mac и телефон

Сеансы Claude Code с MacBook видны в том же окне «Сеансы», а с телефона и Mac список можно открыть в браузере. Условие одно: устройства должны быть в одной сети Wi-Fi с этим ПК.

**Подключение устройства:**

1. На ПК откройте окно «Сеансы» → иконка **Устройства** в заголовке → **+ Подключить устройство…**
   - В первый раз Windows один раз спросит права администратора. Это нужно, чтобы разрешить вход на порт 47600 только из вашей локальной сети.
2. Окно покажет адрес вида `http://192.168.1.141:47600` и код из 6 цифр.
3. На телефоне или Mac откройте этот адрес в браузере и введите код. Устройство запоминается, поэтому код больше не понадобится.

Страница сделана под палец: крупные кнопки (не меньше 44 px), стеклянная шапка, у каждого сеанса полоска контекста, подробности свёрнуты под «Подробности». Сеанс с запросом выделен рамкой, число ждущих вас видно в названии вкладки, новые сеансы появляются плавно. Если на устройстве включено «Уменьшение движения», анимации нет.
4. **Только на Mac:** на открывшейся странице нажмите **Получить команду установки**. Команда скопируется сама. Вставьте её в Терминал (⌘ Пробел → «Терминал», ⌘ V, Enter). После этого сеансы Claude Code этого Mac появятся на ПК.

В окне «Подключить устройство» сразу видно, что устройство подключилось.

**Вкладка «Устройства»:**

- **Доступ из сети** — тумблер. При выключении подключённые устройства сохраняются.
- Список устройств: зелёная точка — на связи, кольцо — давно не было связи; тип и число сеансов. Последняя строка — **+ Подключить устройство…**
- Правый клик по устройству:
  - **Переименовать** (или двойной клик);
  - **Уведомления на ПК** — показывать ли на ПК уведомления о событиях этого Mac. По умолчанию выключено: Mac сам показывает свои уведомления;
  - **Отключить** (или Del) — устройство сразу теряет доступ.

**Что важно знать:**

- Сеансы в приложении Claude на телефоне отслеживать нельзя: там нет хуков. Телефон только смотрит список.
- Перейти к окну можно только для сеансов этого ПК. Для сеансов Mac видны статус и превью.
- Когда ПК выключен или Mac не дома, события с Mac теряются. Хук ждёт ответа не больше 2 с и работает асинхронно, поэтому Claude не тормозит.
- **Безопасность:**
  - Каждое устройство получает свой токен, а на ПК хранится только его хэш.
  - Код подключения одноразовый: действует 10 минут, после 5 неверных попыток блокируется.
  - Внутри сети данные идут по HTTP без шифрования. Для домашней сети это приемлемо, но в общественной сети Wi-Fi доступ лучше выключать.
- Удалить с Mac: `~/.claude-notifier/uninstall.sh`. `uninstall.ps1` на ПК удаляет правило брандмауэра и резервацию порта (с запросом UAC).

Требования к Mac: macOS со встроенными `curl` и `osascript`. Ничего устанавливать не нужно.

## Встроенные уведомления Claude

Desktop-приложение Claude показывает собственные уведомления. Чтобы не получать каждое событие дважды, выключите их в настройках приложения Claude, в разделе уведомлений Claude Code:

- **Permission request notifications** → Off
- **Question notifications** → Off
- **Task complete notifications** → Off

## Настройка: `%USERPROFILE%\.claude-notifier\config.json`

Файл необязателен. Все поля тоже необязательны. Неверное значение заменяется значением по умолчанию, а в лог пишется WARN.

```json
{
  "events": {
    "done":       { "enabled": true, "sound": "" },
    "permission": { "enabled": true, "sound": "" },
    "error":      { "enabled": true, "sound": "C:\\Sounds\\error.wav" },
    "limit":      { "enabled": false, "sound": "" }
  },
  "limitThresholds": [80, 90],
  "previewLength": 200,
  "approvals": { "enabled": true, "waitSeconds": 600, "cliWaitSeconds": 0, "remindMinutes": 3 },
  "quickReplies": { "enabled": true, "minutes": 60 },
  "showPrompt": false,
  "context": { "enabled": true, "warnPercent": 85 },
  "hotkey": { "enabled": true },
  "stalled": { "enabled": true, "minutes": 10 },
  "longTasks": { "enabled": true, "minutes": 2 },
  "groups": { "enabled": true, "minSessions": 4 },
  "inactive": { "enabled": true, "hours": 2 },
  "notch": { "enabled": true, "screen": "", "position": "center" },
  "quiet": { "enabled": false }
}
```

- `enabled: false` — событие этого типа не показывается.
- `sound` — путь к своему WAV. Пустая строка означает системный звук:

  | Событие | Системный звук |
  |---|---|
  | done | Windows Notify System Generic |
  | permission | Windows Notify Messaging |
  | error | Windows Critical Stop |
  | limit | Windows Battery Low |

- `limitThresholds` — пороги предупреждения о лимите, в процентах.
- `previewLength` — длина превью в уведомлении, от 20 до 2000 символов.
- `approvals` — ответы на запросы разрешения из приложения. `waitSeconds` — сколько хук ждёт решения в приложении Claude (10–3600 с); там диалог Claude показывается одновременно, и решает тот, кто ответил первым. `cliWaitSeconds` — то же для Claude Code CLI; по умолчанию 0 (не ждать), потому что в CLI хук может выполняться до показа диалога и задержал бы его. `remindMinutes` — через сколько минут без ответа повторить уведомление о запросе (0–120; 0 — не напоминать).
- `quickReplies` — быстрые ответы после «Готово»; `minutes` — сколько ждать ответа (1–240 мин).
- `showPrompt` — сохранять начало вашего запроса для подробностей сеанса (по умолчанию нет).
- `context` — уведомление «Контекст почти заполнен»; `warnPercent` — порог (50–99 %). Включается своим тумблером, независимо от уведомлений «Лимит».
- `hotkey` — горячая клавиша мини-окна (Win+Shift+C, запасная — Ctrl+Alt+C).
- `stalled` — уведомление «Сеанс, похоже, остановился»; `minutes` — сколько минут тишины в журнале (3–120). Включается своим тумблером, независимо от уведомлений «Ошибка».
- `longTasks` — «Готово» только после долгих задач: если Claude работал меньше `minutes` минут (1–60) и вы за компьютером, уведомления и звука нет (событие остаётся в истории). Если вы отошли (больше минуты без мыши и клавиатуры), «Готово» приходит всегда.
- `groups` — группировка сеансов по проектам; `minSessions` — от скольких сеансов в списке (2–20).
- `inactive` — строка «Неактивные»; `hours` — через сколько часов ожидания сеанс туда попадает (1–72).
- `notch` — шторка вверху экрана; `screen` — имя монитора (например, `\\.\DISPLAY2`; пусто — второй монитор, если он есть), `position` — `left`, `center` или `right`.
- `quiet` — звук уведомлений выключен (кнопка «звук» в шторке).

## Файлы

Всё лежит в `%USERPROFILE%\.claude-notifier`, а не в `AppData`. Приложение Claude для Windows установлено как пакет MSIX: всё, что его процессы (хуки, установщик, запущенный из Claude) пишут в `AppData`, Windows перенаправляет в личную папку пакета. Такую копию не видят «Пуск», Проводник и Claude Code CLI. Установщик переносит данные со старого места (`%LOCALAPPDATA%\claude-notifier`) сам.


| Путь | Что это |
|---|---|
| `%USERPROFILE%\.claude-notifier\log.txt` | Лог (INFO/WARN/ERROR). При размере больше 1 МБ переносится в `log.1.txt`. Тексты сообщений Claude в лог не пишутся. |
| `%USERPROFILE%\.claude-notifier\history.json` | Последние 100 событий. |
| `%USERPROFILE%\.claude-notifier\sessions.json` | Активные сеансы для окна «Сеансы». Пишет только трей. |
| `%USERPROFILE%\.claude-notifier\network.json` | Доступ из сети и подключённые устройства (только хэши токенов). |
| `%USERPROFILE%\.claude-notifier\limits.json` | Пороги лимитов, которые уже сработали. |
| `%USERPROFILE%\.claude-notifier\session-prefs.json` | Имена, закрепление и «без уведомлений» сеансов (записи старше 30 дней удаляются). |
| `%USERPROFILE%\.claude-notifier\stats\`, `activity\` | Итоги журналов сеансов (контекст, подробности, статистика) и место, где чтение остановилось. Удалять можно: всё пересчитается. |
| `%USERPROFILE%\.claude-notifier\cache\` | Скомпилированные помощники (Win32 и интерфейс). Ускоряют хуки и запуск. |

## Известные ограничения

Проверено вживую 2026-11-16 в desktop-приложении Claude (Windows 11, Smart App Control включён).

1. **Клик по уведомлению не открывает сессию.**
   - Windows 11 передаёт клик по уведомлению только программе, у которой есть собственный `.exe` с COM-активатором. Без него клик по уведомлению с именем «Claude Notifier» открывал окно Microsoft Store («нет программы для этой ссылки»).
   - Собственный неподписанный `.exe` заблокировал бы Smart App Control.
   - Поэтому у уведомлений нет действия по клику: они подписаны «Claude Notifier» с иконкой приложения (через ярлык в меню «Пуск»), и клик просто закрывает их. Переход к сессии — через окно «Сеансы» или «Историю» в трее. Проверено 2026-11-17: с ярлыком и своим AppUserModelID переход по клику всё так же открывает Store. Подробности в ADR-006.
2. **Строка статуса не показывается в desktop-приложении Claude**: проверено, риск R-1. Расход лимитов для полос и предупреждений 80/90 % тогда берётся с сервера Anthropic — но только если вы вошли в Claude Code CLI (у приложения Claude свой вход, его токен программе недоступен). В desktop остаётся уведомление «Ошибка» с `rate_limit`, когда лимит уже исчерпан (хук `StopFailure`).
3. **Конкретный чат в desktop-приложении открыть нельзя**: у Claude нет документированной ссылки на сессию. «История» выводит на передний план окно приложения.
4. **Первое уведомление после старта** приходит примерно через 0,9–1,2 с, потому что трей ещё нужно запустить. Дальше уведомления приходят за 0,13–0,2 с.
5. **Скрипт-посредник** работает около 0,4 с: одна только загрузка `powershell.exe` занимает около 0,16 с. Хуки асинхронные, Claude их не ждёт.
6. **Память трея**: около 60 МБ рабочего набора в простое (лимит 150 МБ) и около 120 МБ приватной памяти. В простое трей возвращает неиспользуемые страницы системе.
7. **Одновременная запись**: если две сессии одновременно запишут историю или пересекут порог лимита, одна пометка может потеряться или уведомление о лимите может прийти дважды.
8. **Ответы из приложения — только для сеансов этого ПК.** Хуки Mac асинхронные и ответа не ждут; сеансы Mac видны, но отвечать на них нужно в Claude на Mac. Быстрый ответ приходит Claude сообщением хука, а не обычным сообщением в чате. Пока сеанс ждёт быстрого ответа, в фоне работает один процесс PowerShell (до `quickReplies.minutes`).
9. **Полупрозрачный фон Mica не используется.** Прототип показал, что в WinForms материал виден только по краям окна: каждый элемент — отдельное окно, для которого DWM рисует сплошной фон. Нужен был бы рендер всего интерфейса на одной поверхности.
10. **Сеанс появляется в окне после первого события.** Сеансы, начатые до установки этой версии, появятся после следующего запроса или ответа.
11. **Claude Code CLI на этом ПК не установлен**, поэтому сценарий CLI проверен только автотестами: поиск окна консоли или Windows Terminal, строка статуса, хуки.

## Разработка

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Test-Syntax.ps1   # синтаксис + UTF-8 BOM
powershell -NoProfile -Command "Invoke-Pester -Path tests"                  # тесты (Pester 3.4, есть в Windows)
```

Все `.ps1` и `.psm1` хранятся в **UTF-8 с BOM**. Windows PowerShell 5.1 читает UTF-8 без BOM как ANSI, и кириллица в таком файле ломает разбор скрипта. Документы проекта (PRD, архитектура, ADR, истории) лежат в `coacoa/docs/`.
